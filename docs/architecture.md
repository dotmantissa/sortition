# How a question moves through Sortition

The operator writes the question, criteria and uncertainty rule, chooses two to five sources, and names a tie source from that same set. Privy verifies the email account. The server verifies that the source hosts are public and submits the complete specification to the registry.

The registry canonicalizes and hashes the specification. Its immutable docket code creates a separate contract for the question. A finalized internal message binds that address to the vault, together with the closing time, the appeal window, the funded hearing deadline and the bonded round limit, so every escrow knows its own lifecycle bounds. The docket also learns its registry and the relay grace period. The database waits for the child contracts to exist before marking registration complete.

The vault accepts the exact resolution fee. Zero is a valid Studio fee. The relayer sponsors native value for fees and bonds from its actual balance. The website never asks the user to sign a wallet transaction. Operator identity and payout ownership are verified from Privy rather than supplied in the request body.

After funding finalizes, the vault sends the docket an authenticated message authorizing the corresponding hearing and naming the panel that round is funded for. Funding also starts that hearing's deadline, measured from the later of the funding time and the registered close. After the registered closing time, the docket independently fetches every source in each validator execution. The registered relay has an exclusive grace period in which to request the jury, so its panel policy applies first; after that any account may request it. The contracts exchange finalized messages rather than making synchronous foreign state reads. Each source independently produces a canonical extracted value, a position, a content digest and a supporting quotation. The model must return the verbatim passage that carries the fact; the contract locates that passage in the document it fetched itself and stores the window around it, so the retained evidence is the passage a reader needs rather than an arbitrary document prefix. That matters for minified JSON and HTML, where the relevant fact can sit far past the opening characters. A document larger than the offered budget is reduced to its opening, its closing and windows around terms derived deterministically from the locked specification, so a fact deep inside a large document is still citable.

Retrieval distinguishes a missing document from an unavailable one. A 2xx body is evidence. A 4xx answer is a repeatable statement that the document is absent, and feeds the disagreement rule as an unreachable source. A timeout, a 5xx, a 408 or a 429 is retried and then raises a transient error, which fails the hearing instead of recording a final UNRESOLVABLE verdict on evidence nobody could read. Validators agree on that failure only when both of them met it, so the hearing stays retryable and, if it never succeeds, the funded deadline returns the money. Raw retrieval cannot run scripts, so a source that yields no position is read a second time through a rendered browser read before being recorded as unknown.

A second audit stage receives the real document window around each quotation, the locked closing time, the first hearing's record of each source and the candidate outcome. It decides two things: whether every stored quotation actually supports the value and position it was stored for, and whether the locked uncertainty definition applies. Mere presence of the quoted text in the document is not support. An unsupported quotation rejects the execution and forces consensus to retry rather than recording it. Because the audit sees document text rather than only short values and digests, a definition that depends on a reporting date, a correction notice or a relationship between sources can be evaluated; when it depends on a fact that cannot be determined from the supplied evidence, the honest answer is uncertainty rather than a guess.

A custom validator reruns the entire extraction and audit. It requires agreement on everything that decides the outcome: the outcome itself, the uncertainty flag, source identity, reachability, position, the normalized extracted value and whether the source changed since the first hearing. It also requires the leader's quotation to occur in the document this validator fetched itself, which binds the evidence without demanding identical provenance. A different whole document digest or an alternative valid citation no longer breaks a hearing whose factual conclusions agree, while invented evidence still cannot pass. Empty and oversized values reject execution.

Unanimity requires every registered source to be reachable and agree. Majority requires more than half of the entire registered source set, including unavailable sources in the denominator. The tie source rule requires every source to have a clear position; the named source then decides a disagreement. The global uncertainty definition takes precedence over a satisfied disagreement rule. Every validator evaluates it against its own complete source readings. Missing or ambiguous evidence also produces UNRESOLVABLE when the locked rule cannot be satisfied. A malformed model response rejects execution and triggers consensus retry rather than masquerading as an evidence verdict.

A funded challenge opens the next docket round, up to the registered bonded round limit of three, which keeps the escalating panel inside the range this deployment can actually seat. Bonds double with each round. The vault names the required panel when it authorizes each round and the docket stores it with the ruling, so the requirement is a public on chain commitment rather than a service setting. The durable worker requests exactly that panel: 5, then 7, 9 and 11. GenLayer chooses their identities.

GenLayer does not expose the seated panel to contract code, so a contract cannot enforce its own panel size. Enforcement therefore happens where it can be checked: after each hearing the service compares the public receipt with the contract's commitment and publishes the result, counting the leader and every validator and recording whether any independent validator took part. Studio supports leader only execution, so a hearing with no independent validator is published as an unverified panel rather than presented as consensus, the widget says so, and the reference consumer refuses to act on it. A production jury security claim still requires validation on the intended production network.

A rehearing cannot read the document the first jury read, because the sources are live URLs and nothing is snapshotted on chain. Instead each hearing records its own digest, quotation and window, and every later hearing receives the first hearing's record together with the locked closing time, and flags each source that has changed since. A later verdict that differs can therefore be attributed to a changed source rather than silently to a mistaken earlier jury. Both model stages are told to judge the question as of the locked closing time and to ignore anything the document presents as later. Each new transaction is a fresh random draw. The application never promises that a fresh draw excludes every participant from a different transaction. Native protocol appeals are paused on this Studio deployment. A real appeal reran validators against the applied state and subsequent recomputation returned absent_runner_comment. The public receipt is retained in deployments/native-appeal-attempt.json. The API and worker reject new native appeals before broadcasting; the UI directs users to bonded hearings. The SDK appeal operation returns the original consensus transaction ID; the worker polls that same ID, refreshes finalized contract state and then completes the appeal.

Every funded hearing has a bounded exit. Funding, and each accepted challenge, sets a deadline for the ruling that round owes. If that deadline passes and the round still has no ruling, any account at all can release the docket: every bond returns to the account that actually paid it, the resolution fee returns to its funder, the outcome becomes REFUNDED and the docket is locked against further hearings. It requires no relay, no operator and no further consensus, so a hearing that consensus can never complete, an extraction that keeps failing or an abandoned question can no longer lock value indefinitely. A ruling that arrives after a refund is accepted quietly and changes nothing, so an in flight hearing cannot fail noisily or reopen a closed escrow. The service queues this release itself once a hearing is overdue, but only when it has no hearing of its own in flight; the permissionless contract call is always available regardless.

After a ruling becomes final, its docket sends the vault the consensus bound outcome, round and criteria hash. The vault authenticates the sender, verifies the expected funded round and opens a fresh fifteen minute challenge window. A prolonged native appeal cannot consume this application window. A window opens once per round and cannot be extended by repeating the call. A production deployment should choose a longer window appropriate for its source cadence and network finality.

Final settlement requires an expired docket appeal window and a completed reading for every funded challenge. Each bond records both its claimant and its economic payer. Winning bonds and proportional shares of losing bonds are credited to the payer. A sponsored bond therefore returns to its sponsor even if the claimant wins. When no challenge backed the final result, the pool is forfeited to the treasury. Integer division dust also goes to the treasury. Registering a question and losing a sponsored self challenge cannot create user profit. The resolution fee goes to the treasury. Credits can be withdrawn only to their named beneficiary. No administrator can choose a verdict or redirect a beneficiary's credit. Wallet withdrawals emit an empty EVM transfer message. The service waits for the resulting payment to finalize successfully before marking the operation complete, then confirms the durable payment record.

Payment reconciliation does not depend on the relay. A pending payment blocks the next withdrawal, so the beneficiary can confirm delivery of their own payment: they are the only party who could lose anything by doing so. A failed external payment does not return its value automatically, so restored credit must arrive with exact native backing, but any account may supply it, including the beneficiary, which means recovery never waits for the relay to be available and funded. Both calls still require the matching payment ID and a pending payment, and neither can be replayed. The worker also scans contract payment state for every account that can hold credit in a settled escrow, so a pending payment from a direct contract withdrawal this service never submitted is still discovered and reconciled.

A withdrawal belongs to a beneficiary rather than to a question, so it no longer occupies a question's exclusive operation slot, and the API requires the caller to have a real stake in the escrow and real withdrawable credit before queueing one. An unrelated account can therefore no longer block a docket's queue with a withdrawal it could never complete.

The public API indexes finalized contract state. Provisional verdicts are displayed as provisional. A settlement consumer receives PENDING until the vault finalizes, and REFUNDED when a hearing was released at its deadline, which is final and explicitly not an adjudication. Every settlement response states when its view was indexed and whether that view is lagging, so delayed discovery of a direct on chain action is visible rather than silent.

On request, a settlement is served with an operator signed attestation: an EIP-191 signature over a fixed, field by field statement that an EVM contract can rebuild and check with `ecrecover`. It authenticates the publisher of the record, which is strictly more than an unauthenticated HTTPS body offers, and it is not a bridge: it does not prove GenLayer consensus to another chain. A production consumer must still verify GenLayer state through its own bridge or oracle before moving funds.

Settlement indexing is crash safe. A question's settled status and its outbox event are written in one transaction, because a crash between them used to lose that event permanently: later idle scans skip settled questions. A repair pass replaces any settlement event an earlier interrupted index lost. Ordinary indexing and payment recovery also keep running under continuous job traffic, so sustained submissions can no longer starve an unrelated update such as a newly expired challenge window.

The worker serializes submissions behind a database lease. Idempotency keys prevent duplicate HTTP writes. A crash during submission without a recorded hash is marked for review; it is never blindly retried. Factory messages are asynchronous, so successful parent finalization alone does not complete registration. Funding delivery can be replayed without paying again; a missing ruling delivery can be republished from the docket. Both repairs emit only after their own finality and preserve the original funding and immutable ruling. Jobs and webhook events persist in Neon across restarts. Polls have due times and backoff so one stalled transaction cannot monopolize the queue. Failed idle indexing backs off independently. Webhook delivery has its own failure boundary. Authenticated participants can retry a funded rehearing without posting another bond. The UI shows pending hearings and window preparation explicitly.

Studio is a development network. Its clock can differ from the web server clock, so closing and dispute checks use the network timestamp. Contract code is pinned to a concrete GenVM runner. The deployed registry holds that code permanently; changing it requires a new registry.

Sponsored payments are limited to 1,000,000,000 GEN wei each, 10,000,000,000 per account per UTC day and 1,000,000,000,000 across the service per UTC day. Reservations use a serializable database transaction before broadcasting. The sponsored Studio experience does not put a user's money at risk, and for that exact reason it is not economic deterrence: a challenger who risks nothing is not discouraged from disputing a correct result. Escalating bonds and a bounded round count limit how much sponsorship a dispute can consume, but they do not create a personal penalty. The vault supports a claimant funding their own bond directly, with proceeds credited to that payer, and the docket publishes the exact vault call, arguments and value for doing so. Production dispute incentives require those genuinely user funded bonds.

Forfeited value leaves the relay. When no challenge backed the final result, the pool and the resolution fee are credited to the deployed treasury, which is a verifiably unspendable address rather than the relay. Sponsoring a losing challenge is therefore a real, permanent cost to the operator instead of a round trip.

New docket resolution calls require the immutable registered relay. This closes direct callers bypassing the relay's requested panel policy. The relay requests normal consensus and growing panels, but Studio remains a development simulator that supports leader only execution. A production jury security claim requires validation on the intended production consensus network. Historical contracts remain immutable and readable; the current service refuses new funding or challenges through archived vaults.

The widget pins the expected question, criteria, network and docket when supplied, and reports an unverified panel or a lagging record rather than presenting either as a clean verdict. It rejects inconsistent finality, hides a previous question's state immediately and deduplicates notifications during its mounted lifetime. A venue must persist its own settlement identity before applying a financial effect. The reference webhook consumer verifies the signature including event ID, validates the pinned specification and reads finalized vault state before recording one action per question. This reference ledger does not control Polymarket positions or move funds on another chain.
