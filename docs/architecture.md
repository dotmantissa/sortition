# How a question moves through Sortition

The operator writes the question, criteria and uncertainty rule, chooses two to five sources, and names a tie source from that same set. Privy verifies the email account. The server verifies that the source hosts are public and submits the complete specification to the registry.

The registry canonicalizes and hashes the specification. Its immutable docket code creates a separate contract for the question. A finalized internal message binds that address to the vault. The database waits for the child contracts to exist before marking registration complete.

The vault accepts the exact resolution fee. Zero is a valid Studio fee. The relayer sponsors native value for fees and bonds from its actual balance. The website never asks the user to sign a wallet transaction. Operator identity and payout ownership are verified from Privy rather than supplied in the request body.

After the registered closing time, the docket reads the vault and then independently fetches every source in each validator execution. Each source independently produces a canonical extracted value, a position, a content digest and a supporting quotation. The model selects a source line number; the contract saves that actual line rather than asking the model to reproduce a quotation. Cross source agreement is applied afterwards. The quotation must occur in the fetched document. A custom validator reruns the entire extraction and global uncertainty evaluation. It compares every stored evidence field exactly, including outcome, uncertainty applicability, source identity, extracted values, positions, reachability, document digests and quotations. Empty supported values and oversized values reject execution. Changing documents or different citations can cause disagreement; the network must reach a new consensus rather than store unverified provenance.

Unanimity requires every registered source to be reachable and agree. Majority requires more than half of the entire registered source set, including unavailable sources in the denominator. The tie source rule requires every source to have a clear position; the named source then decides a disagreement. The global uncertainty definition takes precedence over a satisfied disagreement rule. Every validator evaluates it against its own complete source readings. Missing or ambiguous evidence also produces UNRESOLVABLE when the locked rule cannot be satisfied. A malformed model response rejects execution and triggers consensus retry rather than masquerading as an evidence verdict.

A funded challenge opens the next docket round. Bonds double with each round. The durable worker queues a new resolution transaction after the bond finalizes and requests panels of 5, 7, 9 and successively more validators. GenLayer chooses their identities. Each new transaction is a fresh random draw; a native protocol appeal additionally rotates the committee under the protocol rules. The application never promises that a fresh draw excludes every participant from a different transaction. Native appeals support Accepted, Undetermined, LeaderTimeout and ValidatorsTimeout decisions while the protocol allows them. The SDK appeal operation returns the original consensus transaction ID; the worker polls that same ID, refreshes finalized contract state and then completes the appeal.

After a ruling becomes final, the vault opens a fresh fifteen minute challenge window. A prolonged native appeal cannot consume this application window. A window opens once per round and cannot be extended by repeating the call. A production deployment should choose a longer window appropriate for its source cadence and network finality.

Final settlement requires an expired docket appeal window and a completed reading for every funded challenge. Each bond records both its claimant and its economic payer. Winning bonds and proportional shares of losing bonds are credited to the payer. A sponsored bond therefore returns to its sponsor even if the claimant wins. When no challenge backed the final result, the pool is forfeited to the treasury. Integer division dust also goes to the treasury. Registering a question and losing a sponsored self challenge cannot create user profit. The resolution fee goes to the treasury. Credits can be withdrawn only to their named beneficiary. No administrator can choose a verdict or redirect a beneficiary's credit. Wallet withdrawals emit an empty EVM transfer message. The service waits for the resulting payment to finalize successfully before marking the operation complete, then confirms the durable payment record. A failed emitted payment queues a restoration that must replenish the exact native amount before credit is restored. Confirmation and restoration require the relay, the matching payment ID and a pending payment; neither can be replayed.

The public API indexes finalized contract state. Provisional verdicts are displayed as provisional. A settlement consumer receives PENDING until the vault finalizes. A foreign chain cannot authenticate this HTTP response by itself. A production consumer must verify GenLayer state through its own bridge or oracle before moving funds.

The worker serializes submissions behind a database lease. Idempotency keys prevent duplicate HTTP writes. A crash during submission without a recorded hash is marked for review; it is never blindly retried. Factory messages are asynchronous, so successful parent finalization alone does not complete registration. Jobs and webhook events persist in Neon across restarts. Polls have due times and backoff so one stalled transaction cannot monopolize the queue. Failed idle indexing backs off independently. Webhook delivery has its own failure boundary. Authenticated participants can retry a funded rehearing without posting another bond. The UI shows pending hearings and window preparation explicitly.

Studio is a development network. Its clock can differ from the web server clock, so closing and dispute checks use the network timestamp. Contract code is pinned to a concrete GenVM runner. The deployed registry holds that code permanently; changing it requires a new registry.

Sponsored payments are limited to 1,000,000,000 GEN wei each, 10,000,000,000 per account per UTC day and 1,000,000,000,000 across the service per UTC day. Reservations use a serializable database transaction before broadcasting. The sponsored Studio experience does not put a user's money at risk; production dispute incentives require user funded bonds. The vault supports a claimant funding their own bond directly, with proceeds credited to that payer.

New docket resolution calls require the immutable registered relay. This closes direct callers bypassing the relay's requested panel policy. The relay requests normal consensus and growing panels, but Studio remains a development simulator that supports leader only execution. A production jury security claim requires validation on the intended production consensus network. Historical contracts remain immutable and readable; the current service refuses new funding or challenges through archived vaults.

The widget pins the expected question, criteria, network and docket when supplied. It rejects inconsistent finality, hides a previous question's state immediately and deduplicates notifications during its mounted lifetime. A venue must persist its own settlement identity before applying a financial effect. The reference webhook consumer verifies the signature including event ID, validates the pinned specification and reads finalized vault state before recording one action per question. This reference ledger does not control Polymarket positions or move funds on another chain.
